Дата: 25.11.2026. Источник дизайна: `open-rmbt-android` (приложение NetCheck).

## 1. Что сделано (часть 1)

- Новый Gradle-модуль `ui/` → артефакт `tj.zehn.rmbt:rmbt-sdk-ui` (Android library, minSdk 24,
  compileSdk 37, view binding). Зависит от `rmbt-sdk` через `api`, публикуется в GitHub Packages
  тем же release-workflow; CI собирает release-AAR и гоняет lint.
- Публичный API: `RmbtUi.configure(RmbtUiConfig(controlUrl, apiKey, tag, appName))`,
  `RmbtUi.start(context)`, `RmbtUi.intent(context)`; фрагменты для встраивания
  `RmbtHomeFragment`, `RmbtHistoryFragment`.
- Экраны (layout'ы скопированы из приложения, data binding заменён на view binding):
  - **Главный** (`fragment_home`): фон по состоянию сети, логотип, кнопка старта с иконкой сети и
    уровнем сигнала, пульсация и кольца, подсказка «нажмите для старта» через 2 с, тип и имя сети,
    «хороший сигнал», «нет подключения», волна, карточка последнего теста.
  - **Тест** (`activity_measurement` + `measurement_bottom_view`): S-кривая с прогрессом шага и
    скоростью, нижняя панель пинг/загрузка/передача, «Шаг N из 4» с пояснением, живой график
    скорости, подтверждение отмены (кнопка и системный «назад»), экран не гаснет.
  - **Результат** (`activity_results`): дата/время, сеть, вердикт с цветной подложкой и шкалой,
    загрузка/передача/пинг с иконками и оценками, блок «Сеть» (тип, сервер), шаринг текстом.
  - **История** (`fragment_history`): список с иконкой сети, временем («Сегодня, 12:00»), общей
    оценкой и тремя значениями; пустое состояние; тап открывает результат.
  - Хост-активити с нижней навигацией «Главная / История», вкладки сохраняют состояние.
- Ресурсы (73 drawable, шрифты Roboto, цвета, размеры, стили, строки **en/ru/tg**) собраны
  автоматически по ссылкам из layout'ов и кода; все переименованы с префиксом `rmbt_`
  (`resourcePrefix` в Gradle), чтобы не перекрывать ресурсы приложения-хоста.
- Данные: история и `clientUuid` хранятся на устройстве (SharedPreferences, JSON, до 500 записей).
  Оценки (плохо/норм/хорошо/отлично) считаются локально по порогам приложения
  (загрузка 5/10/100, передача 2,5/5/50 Мбит/с, пинг 75/25/10 мс).
- Проверено: `assembleDebug`, `assembleRelease`, `lintDebug` (0 ошибок), тесты ядра
  `:rmbt-sdk:jvmTest`. **Не проверено: запуск на устройстве/эмуляторе** — нет демо-приложения.

Убрано относительно приложения (не нужно на этом этапе): loop mode, режим покрытия, QoS, карта,
статистика, настройки, Pro/expert-данные (сигнал в дБм, частоты, соты, GPS-скорость), фильтры,
синхронизация и экспорт истории.

## 1а. Встраивание в MyTelecom-Android (сделано)

- Вкладка «Скорость интернета» в нижней панели после «Истории»: `RmbtHomeFragment` через
  `AndroidFragment`; «Ещё» → «История тестов скорости» открывает `RmbtUi.startHistory`.
- Доработки SDK для встраивания: `RmbtFragment` (своя AppCompat-тема — хост может быть не AppCompat;
  статус-бар возвращается хосту на паузе), `RmbtActivity` + `RmbtUiConfig.wrapContext` (язык,
  выбранный внутри приложения), `RmbtHomeFragment.setContentBottomPadding` (плавающая панель хоста),
  `RmbtHistoryActivity` / `RmbtHistoryFragment.withBackButton()`.
- Совместимость: SDK собирается Kotlin 2.3.21 (было 2.4.21) и serialization 1.11.0 (было 1.13.0),
  чтобы его читали приложения на Kotlin 2.2+ (MyTelecom — 2.2.10); AGP 9.2.1 и Gradle 9.7.1 — как в
  MyTelecom (в составной сборке AGP должен совпадать).
- **Исправлен баг ядра**, из-за которого тест на Android не проходил никогда: `RmbtClient.start()`
  выполнялся в потоке сборщика (у UI — главный поток), DNS ktor-сокета падал с
  `NetworkOnMainThreadException`. Теперь `flowOn(Dispatchers.Default)` + `connect` в `Dispatchers.IO`;
  регрессионный тест `RmbtClientThreadTest`. Ошибка теста пишется в logcat (тег `RmbtSdk`).
- Проверено на эмуляторе (Pixel 8, Android 14) на тестовом хосте с той же схемой, что MyTelecom
  (Compose + `FragmentActivity`, не-AppCompat тема, свой язык tg, плавающая панель): вкладка, возврат
  статус-бара, полный тест с реальным бэкендом → результат → карточка → история, альбомный главный
  экран, тест в release-сборке с R8. Сам MyTelecom на устройстве не запускался (нужен вход), только
  `assembleDebug`, `assembleRelease` (R8) и unit-тесты.
- MyTelecom берёт SDK из соседней папки `../../sdk/zehn-speedtest-sdk` (includeBuild), иначе —
  `tj.zehn.rmbt:rmbt-sdk-ui:0.2.0` из GitHub Packages (`GPR_USER`/`GPR_TOKEN`). **Release CI
  MyTelecom соберётся только после выпуска 0.2.0 и добавления токена в секреты.**

## 1б. iOS: `RmbtSdkUI` (сделано, 26.11.2026)

Источник дизайна — `open-rmbt-ios` (NetCheck). Экраны переписаны на SwiftUI (не перенос XIB),
геометрия, цвета, шрифты Roboto и картинки взяты из приложения.

- Продукт **RmbtSdkUI** в том же Swift-пакете (`Package.swift`, код в `ui-ios/`), зависит от `RmbtSdk`.
  Минимальная версия пакета поднята до **iOS 16** (`NavigationStack`); MyTelecom-iOS — 16.0.
- Публичный API: `RmbtUI.configure(RmbtUiConfig(controlUrl, apiKey, tag, appName, language,
  requestLocationPermission))`, `RmbtSpeedtestView` (вкладки «Главная / История»), `RmbtHomeView`,
  `RmbtHistoryView`, для UIKit — `RmbtUI.present(from:)`, `makeViewController(onClose:)`,
  `makeHistoryViewController()`.
- Экраны: **главный** (синий фон с градиентом / серый без сети, кнопка старта с иконкой Wi-Fi или
  мобильной сети и поколением 2G–5G, «дыхание» и кольца, две волны, карточка последнего теста),
  **тест** (тёмный экран, сеть и технология, приборы прогресса и скорости из приложения с подписями
  шагов на en/ru/tg, проценты по таблицам приложения, значения загрузки/передачи/пинга с цветными
  иконками, «Шаг N из 4» с пояснением, живой график, подтверждение отмены, ошибка с «Повторить»,
  экран не гаснет), **результат** (дата и время в заголовке, сеть, вердикт с цветной карточкой и
  шкалой, значения и оценки, «Подробнее»: тип сети и сервер, карта Apple Maps с местом теста,
  «Поделиться» текстом), **история** (список с полоской оценки, иконкой сети, временем «Сегодня 12:00»,
  пустое состояние). Тёмная тема для результата и истории, Dynamic Type, VoiceOver, Reduce Motion.
- Данные: история и `clientUuid` в `UserDefaults` (suite `tj.zehn.rmbt.ui`), JSON такой же, как на
  Android (+ поле `technology`), до 500 записей; сеть — `NWPathMonitor` + CoreTelephony (без разрешений);
  геолокация — одна точка на тест, если хост описал `NSLocationWhenInUseUsageDescription`.
- **Исправлено в ядре** (нужен релиз 0.2.0, иначе iOS не работает вообще):
  1. `RmbtClient.run` без `@Throws` — любая ошибка теста на iOS завершала приложение. Добавлен
     `@Throws(Throwable::class)`, ошибка приходит в Swift как `Error`.
  2. На iOS тест не проходил никогда: ktor не умеет TLS-сокеты на Kotlin/Native («TLS sessions are not
     supported on Native platform»). `Platform.defaultTransport` на iOS — `WEBSOCKET` (wss через
     URLSession), как в вебе.
  3. Память: у WebSocket-клиента ktor очереди кадров по умолчанию без ограничения, и передача за 7 с
     складывала в память гигабайты кадров быстрее, чем их отправляла сеть (на Mac — 17 ГБ; MyTelecom на
     iPhone 16 Pro Max падал с EXC_RESOURCE на лимите 3376 МБ). Очереди ограничены 32 кадрами в каждую
     сторону (`defaultHttpClient`); пик памяти за тест — 54 МБ, скорость передачи не изменилась.
     E2E-тест теперь проверяет рост памяти (< 200 МБ).
- Проверено: 24 unit-теста (Swift Testing: пороги, форматы, чтение истории Android, шаги,
  `MeasurementViewModel` с фейковым движком: события, сохранение, ошибка, повтор, отмена, таймаут
  геолокации); 3 E2E-теста с реальным бэкендом из симулятора (полный тест ↓72–86 / ↑65–75 Мбит/с,
  сервер «Tojiktelecom (Dushanbe)», все 7 фаз по порядку на главном потоке; недоступный сервер →
  ошибка, а не падение; отмена < 5 с); рендер экранов в PNG (en/ru/tg, тёмная тема, крупный шрифт,
  320 pt); демо `sample-ios/RmbtSample.swiftpm` запущено в симуляторе iPhone 17 (главный экран).
  CI: задача `ios-ui` (macOS) собирает XCFramework и гоняет тесты пакета.
- **Не проверено:** полный проход по экранам нажатиями в симуляторе (нет инструмента нажатий —
  экран теста и результат проверены рендером и E2E по отдельности), реальный iPhone, MyTelecom-iOS.
- Встраивание в свою навигацию: `RmbtStartView(onOpenResult:)`, `RmbtHistoryListView(onOpenResult:)`,
  `RmbtResultView(testUuid:)` — без своего `NavigationStack`, переходы делает приложение.
- **Главный экран — один в один с Android** (`rmbt_fragment_home.xml`): градиент #0072EF→#004787,
  круг-картинка на 35 % высоты, иконки сети из Android (векторы → SVG), кольца 0.78→1.05 и «дыхание»,
  подсказка «Нажмите кнопку…» через 2 с, волна из двух спрайтов, без сети — серый фон, «Нет подключения к
  интернету!» и диалог по нажатию, карточка последнего теста с Android-иконками и «Сегодня, 09:10».
  Отличие: iOS не даёт уровень сигнала, поэтому иконка Wi-Fi/мобильной сети всегда полная, и нет имени
  Wi-Fi/оператора — показывается тип сети. Экран теста остаётся по open-rmbt-ios.
- **Результат и история — один в один с Android** (`rmbt_activity_results.xml`, `rmbt_fragment_history.xml`):

## 3. Поведение теста

3.1. **Фоновое выполнение.** Сейчас тест идёт в `ViewModel` и обрывается, если система убьёт
процесс или пользователь смахнёт приложение. В NetCheck тест идёт в `MeasurementService` с
уведомлением. Сделать foreground service (уведомление с прогрессом и отменой), экран теста
подписывается на сервис.
*Приёмка:* тест доходит до конца при свёрнутом приложении и выключенном экране.

3.2. **Пинг и сервер во время теста.** Ядро отдаёт пинг и имя сервера только в итоговом
`RmbtResult`, поэтому пинг появляется в конце, а блок «Сервер» с экрана теста убран.
Нужно расширить ядро (новая минорная версия): например `RmbtEvent.Phase` с необязательными
полями или отдельные события. Важно: новый подкласс `RmbtEvent` ломает исчерпывающий `when` у
текущих клиентов — согласовать вариант, описать в changelog.
Сейчас фазы INIT и PING показываются прогрессом по времени (3 с и 1,5 с, максимум 95 %) —
после доработки ядра заменить на реальный.

3.3. **Тип мобильной сети (LTE/5G) и SSID.** Без разрешений показываются «Мобильная сеть» и
«Wi-Fi». Если у хоста уже есть `READ_PHONE_STATE` / геолокация — показывать технологию и SSID
(SSID уже читается при выданной геолокации). Сам SDK разрешения не запрашивает.

3.4. **Ошибки.** Сейчас любая ошибка → один диалог «Тест не выполнен». Различать: нет сети,
Control Server недоступен, ошибка сервера, обрыв измерения; кнопка «Повторить».

## 4. История

4.1. **Серверная история.** В NetCheck история грузится с Control Server (`/history` по
`clientUuid`) и видна после переустановки/с других устройств. Сейчас — только локально.
Решить: оставить локальную как кэш и добавить загрузку с сервера (pull-to-refresh, состояния
загрузки/ошибки есть в исходном layout'е).

4.2. Удаление записи и очистка истории (с подтверждением/Undo).

4.3. Фильтры по типу сети/устройству — как в приложении, если нужны продукту.

4.4. Версия схемы хранения (`schemaVersion`) и миграция при изменении полей.

## 5. Экран результата

5.1. Графики скорости по времени (в приложении — Pro-функция, `ViewPager` + вкладки), карта,
QoE/QoS, «Подробности теста» — требуют `/testresult` и `/testresultdetail` Control Server.
5.2. Шаринг картинкой-карточкой (`ResultShare.card` в приложении), сейчас только текст.
5.3. Ссылка на открытые данные по `openTestUuid`.

## 6. Кастомизация для приложений-хостов

6.1. **Бренд.** В SDK сейчас логотип NetCheck (`rmbt_ic_brand_logo*`) и его цвета. Нужно:
параметр логотипа/цвета в `RmbtUiConfig` или документированное переопределение ресурсов
`rmbt_*` хостом; решить, допустим ли логотип NetCheck в чужих приложениях.
6.2. **Тёмная тема** — в исходном приложении её нет; при необходимости сделать `values-night`.
6.3. **Колбэки хосту:** тест начат/завершён/ошибка (для аналитики), открытие своего экрана
вместо `ResultActivity`.
6.4. **Compose.** Командные правила UI предписывают Compose; текущий перенос сделан на Views ради
точной копии. При необходимости — Compose-обёртки (`AndroidView`) или переписывание.
6.5. iOS — см. 1б (те же доработки 3–6 нужны и там). Web UI — отдельное ТЗ.

## 7. Релиз

7.1. Выпустить версию с UI-модулем (`gh workflow run release -R Hadamot/zehn-speedtest-sdk -f version=0.2.0`):
workflow уже публикует `rmbt-sdk-ui`. Проверить установку в чистый проект по README.
7.2. Changelog: новый артефакт, ограничения из разделов 3–6.
7.3. R8/ProGuard: рефлексии нет, consumer-правила не требуются — подтвердить сборкой демо с
`minifyEnabled true`.

## Справка для разработчика

- Код: `ui/src/main/kotlin/tj/zehn/rmbt/ui/` — `screen/` (экраны и ViewModel), `view/`
  (скопированные view: кривая, волна, график, карточка), `data/` (история, монитор сети),
  `model/`, `util/` (перенос binding adapters и утилит приложения).
- Ресурсы теперь ведутся в `ui/src/main/res/` (имена с `rmbt_`); при изменении дизайна в
  приложении — переносить вручную (скрипт переноса в репозиторий не добавлен).
